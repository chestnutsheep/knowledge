# 知识库系统化审阅与改进方案

> 审阅对象：`/home/AI/笔记/知识库`（共 2775 篇 md、652 个 pdf、约 3300+ 文件）
> 审阅日期：2026-09-13 ｜ 方法：全库脚本化扫描 + 关键笔记抽样 + 索引层通读
> 目标：在现有双schema强约定基础上，使其更**详细、清晰、可快速检索、且行业/产业链可视化**。

---

## 0. 结论摘要（先看这里）

**优势（已具备，应保留并放大）**
- Frontmatter 采用率 **98.2%**（2727/2775），Wikilink 采用率 **96.3%**（2672/2775）—— 已是"可生长"知识库的良好地基。
- 已自发形成 **两套语义 schema**：研报 schema（2536 篇，含 concept/org/rating/industry 等）与产业概念 schema（含 Component/Raw-Material/Impact-Direction 双维度检索）。
- 已有成熟的 **三层连接框架**（Raw 研报 → Auto-index 概念卡片/时间线/速览 → Wiki 概念底稿），见 `00-研报知识框架.md`。
- 孤儿率仅 **3.7%**，双向链接习惯好；概念卡片设计质量高（共识综述 + 逆检索）。

**四大待改进缺口（直接对应你的目标）**
1. **可快速检索**：2536 篇研报**平铺在单一文件夹根**（无每行业 MOC、无分桶），Quick Switcher / 图谱在 2500+ 文件下事实失效；检索几乎全依赖 Dataview。
2. **更清晰 / 一致性**：两套 schema 字段不统一；`status` 生命周期基本未用（仅 2 篇且取值非法）；`confidence` 仅在产业侧（且枚举为"待验证/已验证/存疑"，未标准化）；根目录存在 **3 份重叠 dashboard 配置**。
3. **更详细**：缺少"成熟度信号"与"待调研 Open Questions"，内容是否过时无法一眼识别；文档与现实存在漂移（框架页写"15 张概念卡片"，实际 14 张）。
4. **产业链可视化**：全库仅 **3 个 canvas + 1 个 drawio + 15 处图表块**；产业链可视化靠单篇范例（`产业链传递总览` 的 InP 链条），未形成每行业一张图的体系。
5. **隐藏风险**：检测到 **234 个失效 wikilink 目标**（含生成器 bug 的尾斜杠 `概念卡片/周期资源品\`、跨库残留 `../01-Macro/...`、占位符 `概念卡片/xxx`），需一次性修复。

> 核心矛盾：**80%+ 的内容量压在「肆」一个平铺区**，而真正"行业研究"的层级化结构在「贰」（仅 116 篇）。检索体验被体量失衡拖累。

### 1.2 组织方式
- **两套 schema 并存，互不统属**：
  - 研报 schema：`title, source, concept, org, declareDate, rating, object, pdfUrl, pdfAvailable, industry, analyst, forecast, tags`。
  - 产业 schema：`tags, Component[], Raw-Material[], Functional-Material[], Impact-Direction[], Area, Type, Confidence, Data-Timestamp`。
- **MOC 层薄**：仅顶层 `知识库总览` + 14 张概念卡片 + 个别行业范例（能源规划、产业链传递总览）。**没有"每行业一张 MOC"**，读者进不去细分赛道。
- **状态机缺失**：`status` 字段近乎空白（2 篇，取值 `continuous- update`、`in-progress` 均非法），无法判断笔记成熟度。

### 1.3 信息展示与检索
- 索引层（`知识库总览`、`检索台`、`00-研报知识框架`）**强依赖 Dataview + Charts 插件**（全库 23 处 ```dataview、15 处图表）；插件关闭或非 Obsidian 打开即失效。
- Dataview 的 `FROM` 多为**硬编码文件夹枚举**（`FROM "贰 • 杂学" OR ...`），结构一变动即破碎。
- **交叉链接存在但不对称**：1482 篇研报已链向「贰 杂学」行业笔记（好），但产业侧是否回链研报主要靠概念卡片"逆检索"，缺统一 `related` 字段。

### 1.4 产业链可视化现状
- 仅：`研报概念架构.canvas`、`第四代核反应堆关系脉络图.canvas`、`TMSR Canvas.canvas`、`芯片元件架构图.drawio`，外加 `产业链传递总览` 的 InP 链条图（bar + 双向索引表）。
- 概念卡片是**列表式**聚合（共识综述 + 研报清单表），未升级为可视化产业地图。
- 产业笔记（如 `AI PC 产业链全景图`）内容详实（callout + 表格 + 来源），但是**文本表格而非图谱**，可一键转 canvas。

### 1.5 一致性 / 质量隐患
- **断链 234 个**：典型为生成器尾斜杠（`概念卡片/周期资源品\`）、跨库残留（`../01-Macro/01-宏观定位`）、占位符（`概念卡片/xxx`）。
- **Dashboard 三件套重叠**：`dashboard.md` / `仪表盘.md` 均带 `dashboard: true` 配置；`复盘与持仓.md` 另含行情字段——职责重叠，建议合并为单一仪表盘。
- **文档-现实漂移**：框架页称"15 张概念卡片"，实为 14；"11 个概念底稿"需核对是否齐备。

## 二、改进方案

> 设计原则：**不推倒重来**。在现有双 schema + 三层框架之上，引入 obsidian-industry-wiki 的"可生长"机制（原子化 / 状态机 / 双向链接 / Open Questions），把"每行业 MOC + 每行业一张产业链 canvas"变成标准件。

### 2.1 目标架构（在现结构上叠加，不动存量）
```
零 • 导览/            ← 统一入口：知识库总览(静态MOC) + 检索台 + 行业MOC索引
贰 • 杂学/            ← 行业研究（保留01–14层级）
    └─ 每行业加：XX产业链.canvas + 00-XX行业MOC.md
叁 • 国家政策/        ← 保留
肆 • 机构观点/
    ├─ 研报_*.md       ← 保留（建议按 concept 分桶到子目录，解平铺）
    ├─ 概念卡片/        ← 升级为"行业MOC"：顶部嵌canvas + 下游环节/上游材料/关联研报
    └─ _index/          ← 时间线/速览/诊断报告
伍/玖/拾/笺           ← 保留
90-标准件/            ← 新增：统一 frontmatter 模板、行业MOC模板、产业链canvas模板
```
- **解平铺**：将 2536 篇研报按 `concept`/`industry` 自动分桶到 `肆 • 机构观点/按行业/<行业>/`，使 Quick Switcher 与图谱可用（脚本批量迁移，链接自动更新）。

### 2.2 统一 Frontmatter Schema（向后兼容，双 schema 收敛为一套）
```yaml
title:            # 必填，与 [[wikilink]] 一致
type:  report|industry|company|trend|concept|source|moc   # 统一枚举
status: seedling|budding|evergreen|archived              # 新增强制：成熟度状态机
industry:         # 主行业（半导体/创新药…）聚合键
sector:           # 细分赛道（可选）
# —— 研报侧（type=report）——
concept:          # 概念/半导体/先进封装
source:  org+分析师   # 原 source/org/analyst 收敛
rating:  object: declareDate: pdfUrl: pdfAvailable: forecast:
# —— 产业侧（type=industry/concept）——
Component: []     # 部件维度
Raw-Material: []  # 原材料维度
Functional-Material: []
Impact-Direction: []
Area:  Type:
# —— 统一元数据 ——
confidence: high|medium|low   # 取代"待验证/已验证/存疑"，全库统一
verified: false               # 是否经核实（布尔）
tags: []
related: []       # 出链（强制≥1，解不对称）
sources: []       # 来源URL/[[来源笔记]]
created: updated: # YYYY-MM-DD，强制
open_questions: [] # 待调研问题，驱动生长闭环
```
> 关键：新增 `status` 状态机 + 统一 `confidence` 枚举 + 强制 `related`/`updated`，这是"更详细、可判断时效"的最小改动。存量笔记脚本批量补 `status: evergreen`、`confidence` 映射即可。

### 2.3 检索优化（快 + 稳）
1. **每行业一张 MOC**（`00-XX行业MOC.md`）：顶部行业定义 → 下游环节表 → 上游材料表 → 关联研报（Dataview）→ 嵌产业链 canvas。这是进细分赛道的唯一入口。
2. **降低插件依赖**：索引层保留 Dataview 实时查询，但**额外提供静态 MOC 列表**（手写 `[[行业MOC]]` 链），保证无插件也能导航。
3. **Dataview 改用标签查询**替代硬编码文件夹：`WHERE contains(tags,"机构观点") AND contains(tags,"概念/半导体")` —— 结构变动不再破碎。
4. **统一仪表盘**：合并 `dashboard.md`/`仪表盘.md`/`复盘与持仓.md` 为单一 `仪表盘.md`（或拆为"研究仪表盘"与"持仓仪表盘"两个明确职责的页面）。

### 2.4 产业链可视化体系（你的核心诉求）
- **标准件：每行业一张 `XX产业链.canvas`**（Obsidian Canvas）：节点=环节/公司/材料，边=传导关系（沿用 `产业链传递总览` 的 prev/next/up 约定 + 需求弹性标注）。
- **概念卡片 → 行业 MOC 升级**：在现有共识综述之上，顶部嵌入该行业 canvas、补充"下游需求→中游环节→上游材料"三栏表，并与研报 Dataview 联动。
- **模板化**：在 `90-标准件/` 提供 `产业链canvas模板`（空白节点+连线样例）与 `行业MOC模板`，新行业直接套用。
- **示范先行**：将 `AI PC 产业链全景图`、`InP 链条` 两个高质量文本范例转为 canvas，作为样板推广到 14 个概念卡片对应的行业。

### 2.5 质量与维护（闭环）
- **一次性修断链**：用脚本修复 234 个失效目标（去尾斜杠、清理跨库残留、替换占位符 `xxx`）。
- **引入孤儿/缺口检测**：对齐 obsidian-industry-wiki 的 `index_vault.py` 思路，写**适配本库双 schema 的校验脚本**，定期跑：① 无入链孤儿 ② 无 `related` 笔记 ③ `status`/`updated` 缺失 ④ 概念无对应行业 MOC（缺口）。
- **文档-现实对齐**：框架页"15 张概念卡片"改为动态统计；建立"概念底稿齐备度"检查。
- **生长闭环**：每篇末尾 `open_questions`，下次调研直接续写，配合 `status` 推进。

### 2.6 分阶段落地路线图
| 阶段 | 动作 | 产出 | 风险 |
|---|---|---|---|
| P0 止血 | 修 234 断链；合并 3 份 dashboard；补 `status/confidence/updated` 到存量 | 干净基线 | 低 |
| P1 骨架 | 定统一 schema；写 `90-标准件/` 三模板；建 `00-XX行业MOC` 骨架 | 可复用标准件 | 低 |
| P2 解平铺 | 研报按 concept 分桶到子目录（脚本迁移+链接更新） | Quick Switcher/图谱可用 | 中（需备份） |
| P3 可视化 | 14 行业各出 1 张 canvas + 概念卡片升级为 MOC | 产业链全景可看 | 中（工作量） |
| P4 闭环 | 适配校验脚本 + 定时跑孤儿/缺口；Open Questions 驱动续写 | 自维持生长 | 低 |
