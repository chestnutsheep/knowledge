# 股票产业链深度分析 Recipe

## 概述

对股票池进行"财务指标→同行比较→企业内部→第三方动态→信息面"五位一体的深度分析，输出交互式HTML报告（ECharts可视化）、结构化CSV数据和SQLite数据库。

## 工作流程

### 报告生成

#### 1. HTML可视化报告

使用 **ECharts 5.x** 生成交互式图表，包含：

| 图表类型   | 用途                          | 交互特性                  |
| ------ | --------------------------- | --------------------- |
| 柱状图    | 营收/利润/增速排名                  | hover悬浮提示,红盈绿跌着色      |
| 饼图(环形) | 常用于产业链利润结构或个股的财务指标构成分析。     | **点击下钻**→展开个股明细→返回    |
| 分组柱状图  | 多期对比(如2025vs2026Q1)         | 图例切换                  |
| 散点图    | 用于数据比较，尤其是可对比数据中包含均值，方差的情况。 | 悬浮显示具体数据标签            |
| 雷达图    | 不同个体的异质性比较（五维能力对比）          | **按钮切换**全产业链/单环节(含个股) |
| 玫瑰图    | 核心标的利润构成                    | 面积占比直观                |

**设计规范（重点提醒）**：
- **色彩逻辑**：盈利/正增长 = 红色，亏损/负增长 = 绿色，遵循A股"红涨绿跌"惯例
- **数字精度**：营收1位小数，利润2位小数，百分比1位小数，增速取整
- **主题风格**：用户主动提供方案则按照方案进行设计，未明确说明则默认黑金配色大气简约的设计风格。设计需使用Skills:
#### 3.2 CSV数据文件

- 编码：**UTF-8 with BOM**（强制，否则Excel中文乱码）
- 格式：标准CSV，第一行为表头
- 文件组织：财务数据+综合评级分开保存

#### 3.3 SQLite数据库

- 使用SQL脚本(.sql)形式输出，用户可直接导入sqlite3
- 包含CREATE TABLE + INSERT语句 + 常用查询示例

### Step 4: 质量检查清单

- [ ] 所有图表容器ID与JS中的`document.getElementById()`一一对应
- [ ] `echarts.init()`放在`<body>`底部或`DOMContentLoaded`内
- [ ] ECharts CDN使用国内稳定镜像(`cdn.jsdelivr.net`)
- [ ] CSV文件包含UTF-8 BOM头(0xEF 0xBB 0xBF)
- [ ] 表格颜色遵循红涨绿跌
- [ ] Tooltip浮窗数据保留至多2位小数
- [ ] 饼图/环形图支持点击切换/下钻
- [ ] 雷达图支持全产业链/单环节切换

## 重点提醒（基于实战反馈总结）

### ⚠️ 操作须知（必读）

#### 1. HTML生成中的致命陷阱

| 问题 | 表现 | 解决方案 |
|------|------|---------|
| **图表容器ID与JS不一致** | 图表空白不渲染 | `id="ec1"`在HTML中出现的位置必须与`document.getElementById('ec1')`完全匹配 |
| **CDN资源加载失败** | ECharts未定义,所有图表不显示 | 使用`cdn.jsdelivr.net`国内镜像,或准备`unpkg.com`/`npmmirror.com`备用源 |
| **JS语法错误阻断** | 某个图表后的所有代码不执行 | 每个`setOption`必须单独try-catch,或在Chrome DevTools Console中逐行检查 |
| **散点图series配置** | 散点图空白 | `label`对象必须在`series`数组内完整闭合：`series:[{type:'scatter', data:[], label:{...}}]` |
| **容器高度为0** | 图表占位符但不可见 | 必须给`.ec`类设置固定高度(如`height:270px`)而非依赖内容撑开 |

#### 2. 颜色恒久远,一条永流传

**这是最容易被忽略但用户最敏感的细节：**

```
❌ 错误: 盈利=绿色, 亏损=红色 (自然直觉)
✅ 正确: 盈利=红色, 亏损=绿色 (A股市场"红涨绿跌"惯例)
   - CSS: .up { color: #C47B7B; } / .dn { color: var(--leaf-green); }
   - 柱状图: s.p25>0 ? '#C47B7B' : '#3E6B5C'
   - 卡片: .v.pos { color: #C47B7B; } / .v.neg { color: var(--leaf-green); }
   - Tooltip: 正值为红色字体
```

#### 3. 数字精度规范

- **营收(亿数)**: 保留1位小数,如 `382.40亿` → `382.4亿`
- **利润(亿)**: 保留2位小数,如 `107.97亿`
- **百分比**: 保留1位小数,如 `28.2%`
- **增速**: 取整百分比,如 `+243%`
- **N/A处理**: 数据不可用时显示`N/A`,非`0`或`null`

#### 4. Tooltip交互的黄金法则

- 饼图/环形图: 必须同时显示`值`和`百分比`
- 柱状图: 必须显示具体数值,单位清晰(`亿`/`%`)
- 散点图: 必须显示数据点名称+双轴数值
- 所有Tooltip: 数值用加粗红色(#C47B7B)高亮
- 所有数值: 至多保留2位小数,不要出现`107.97000000000001`这种情况

#### 5. 图表交互深度

- 环形图/饼图: **必须支持点击下钻**——点击扇形展开该环节个股明细,点击"返回"恢复总览
- 雷达图: **必须支持模式切换**——全产业链概览↔单环节明细(含个股虚线)
- 不可强行在所有图表上都加交互,只在饼图和雷达图上做深度交互,其他图表以信息呈现为主

#### 6. 数据交叉验证

每份报告必须包含：
- 营收+利润双指标基础核对
- 净利率计算并比对行业均值
- 季度利润与全年利润的可持续性检查
- 毛利率/净利率/ROE/负债率四维异常标记
- 标记规则: ✓正常 | ⚡高增长(需关注持续性) | ⚠异常(需关注原因)

#### 7. 文件编码的"潜规则"

- CSV文件必须用 **UTF-8 with BOM**(0xEF 0xBB 0xBF前缀)
  不带BOM → Windows Excel打开中文乱码 → 用户认为数据损坏
- HTML用UTF-8 without BOM即可(浏览器自适应)

#### 8. 文件输出路径的规范

- 报告文件：输出到股票池所在目录的`analysis/`子目录
- 数据清单：输出到用户的Obsidian知识库对应账号下
- Skill文件：输出到Agent-MCP-Skill仓库的skills/目录
- 所有文件名前缀与股票池名称一致
